# Runner milestone — v0.2 — 2026-10-28

## Delivered slice

Approved plan → resolve source commit → materialize separate tracked-file snapshot → apply explicit edits → run static checks → persist patch/checks/provenance → remove temporary workspace. The original task stays approved; run status is independent and never implies publication approval.

This milestone is a **scoped-edit/static-verification runner**, not natural-language AI code generation. Docker CLI and the standard Docker Desktop installation were absent in this environment, so no untrusted project commands were run on the host. An OS/container-isolated coding-agent and project-test backend remains the next milestone.

## Source and execution boundaries

- Public GitHub source: resolve current branch HEAD through the API at run time, fetch that exact SHA into a temporary Git repository, then read blobs from the pinned tree. Do not trust the last webhook SHA as the authoritative head.
- Local source: operator-controlled mapping only, snapshot the configured repository's committed HEAD, ignoring untracked files and dirty working-tree changes. A local mirror mapping intentionally selects local HEAD; it does not prove that commit equals the current GitHub branch head.
- Private GitHub metadata remains supported by App auth, but private source checkout requires a local mirror in this version. No token is embedded in a Git command or URL.
- Materialize regular blobs only. Reject symbolic links, submodules, unsafe/reserved paths, case collisions, sources over 200 tracked files, files over 1 MiB, or snapshot contents over 10 MiB. These are snapshot bounds, not OS-level disk quotas; Git network fetch occurs before tree size inspection.
- Fixed trusted Node worker accepts 1–20 UTF-8 file edits, at most 256 KiB combined replacement text. Existing-file replacement requires exactly one occurrence of nonempty `before`; new-file creation uses `before: null`. All edits are validated before writes. No deletion/rename/binary-edit mode.
- Trusted worker runs with `--permission`, read/write grants only for its disposable workspace, no addon/child-process/worker grants, a heap cap and a cleaned environment. Repository code is data and is never imported/evaluated. JavaScript checks use `node --check` in separate bounded processes.
- No shell command from a browser request, task intent or repository manifest is accepted. Git hooks/fsmonitor/credential helpers are disabled and system/global Git configs are excluded from subprocesses. No npm install or lifecycle scripts run.
- Node's permissions are a seat belt for trusted code, **not** a security boundary against malicious code. Reference verified with TinyFish: [Node v24.19.0 permissions](https://nodejs.org/download/release/v24.19.0/docs/api/permissions.html). Do not extend this runner to arbitrary agents/tests without OS isolation.

## Lifecycle and evidence

Run states: `preparing` → `running` → `passed` / `failed` / `cancelled` / `timed_out`; process restart marks unfinished records `interrupted`. One active run per task enforced in SQLite; one active run per server process. Busy starts return 409; there is no durable execution queue or multi-server lease.

Default total deadline 60 seconds; each subprocess also has a 30-second timeout and bounded captured output. Cancellation terminates process trees (`taskkill /T /F` on Windows, a separate process group on POSIX). The fixed worker cannot spawn descendants; Git HTTPS helpers are also covered by supervisor tree termination. Network API resolution has its own 15-second bound and completes before the next cancellation checkpoint.

Stored evidence: pinned base SHA, actual unified patch, SHA-256 of patch bytes, named checks with real pass/fail details, summary and timestamps. The list endpoint returns metadata rather than repeated full patch bodies; the detail route returns full evidence. Check names describe scope; `passed` means scoped edits and static checks passed, **not** project tests passing or semantic correctness.

Cleanup only removes the exact `mkdtemp` child under the OS temp directory allocated to the run. Source repositories are never cleanup targets. Cleanup failures are recorded as failed checks. Abrupt process/machine termination can leave temp folders; recovery marks interrupted runs but does not claim orphan cleanup or resume. Graceful shutdown cancels active work before closing SQLite.

## API

| Endpoint | Purpose |
| --- | --- |
| `POST /api/tasks/:id/runs` | `{version, edits:[{path,before,after}]}`; requires current approved GitHub-adapter task; returns 202 |
| `GET /api/runs/:id` | Persisted run evidence |
| `POST /api/runs/:id/cancel` | Cancel owned active run; terminal cancellation is idempotent |
| `GET /api/state` | Run summaries and honest capability flags (`aiAgent:false`, `projectTests:false`, `publication:false`) |

The same loopback Host and mutation Origin/client-header rules apply. No remote service was deployed and no upstream branches/PRs were created.
